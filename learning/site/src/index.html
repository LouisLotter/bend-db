PROOF 01 · NO PROOF BACKGROUND REQUIRED

Every key.
One small argument.

A test asks about an example. A law tells us exactly what must hold for every input it names.

THE CLAIM, IN PLAIN LANGUAGE

Looking up any key in an empty store returns missing.

law empty_is_missing:
  for key: Nat
  {KV.get(KV.empty(), key) == None{} : Maybe<&2, String>}

for key: Nat means every natural-number key. Here, == is an equality proposition to prove, not a Boolean test.


        
What we have established

KERNEL-CHECKED LAWS
Three universal claims
  • Every key is missing from an empty store.
  • Any value can be read immediately after writing it.
  • Any key is missing immediately after deleting it.
bend PROOF.bend --verdict checks the translated definitions and proofs with BendTT’s Lean-built kernel.
STILL OPEN
A specification can be incomplete
Could a put discard all unrelated keys and still satisfy “read after put”? Yes. We still need a law saying that writing one key preserves every different key.
Sixteen concrete cases pass on both native and JavaScript backends. Examples exercise the implementation; they do not replace that missing universal claim.

        
Next proof: why a key equals itself
The write and delete proofs use Nat.is_eq(key, key) == True{}. The helper proves it by induction: zero equals zero; comparing successors reduces to comparing their predecessors. The recursive proof handles the smaller predecessor.
The actual helper states the equality in the opposite direction, True{} == Nat.is_eq(key, key), to fit Bend’s rewrite syntax. Rewriting replaces the comparison with True, so the first entry wins and reflexivity finishes.

        
These laws do not prove durability, complexity, concurrency, the native compiler, the translation to BendTT, or the whole application. Read the exact claims alongside the code.
